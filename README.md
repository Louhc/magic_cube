# 六面魔方工具箱

一个配色编辑器，三张公式速查表。纯 JS，无依赖、无构建步骤。

```
双击 index.html 打开导航页
```

## 白天 / 夜晚

画布右上角切换。整套主色（背景、面板、输入框、文字、强调色）都会跟着变，
OLL 图的墨色也跟着翻。

**切换是淡过去的**（240ms）：颜色全在 `theme.css` 那 44 个变量里，所以把它们按
`@property` 注册成 `syntax:'<color>'`，再在 `:root` 上挂一条 `transition` ——
浏览器就能逐帧算中间色，整页（连按钮那种 `--btn-bg` 渐变底色、阴影、描边）
一起平滑过渡。这样不用给每个元素写 transition，也不会在首屏补一段动画
（首次样式计算不触发 transition，而 head 里的脚本早就把 `data-theme` 定好了）。
过渡包在 `prefers-reduced-motion: no-preference` 里；不认 `@property` 的浏览器
当没这回事，直接切换。

> 时长特意压在 240ms：再长就能感觉到「页面在变色」，反而不像换主题了。
> `test/links.js` 会核对「每个颜色变量都注册了、都在过渡列表里」——
> 以后加变量忘了注册，切换时就会啪一下跳过去，那条会红。

**画成 1px 线的那 4 个颜色不参与过渡**（`--line` / `--line-strong` / `--kbd-line` /
`--toast-line`）：细线在过渡里被逐帧重绘，遇上分数像素比（Windows 125%/150% 缩放）
会反复重新对齐设备像素，看着就是「边框闪一下」—— 主页那六张卡片
（`border:1px` + `border-radius:12px`）最明显。让它们一步到位、其余颜色照旧淡过去，
反而最干净。`test/links.js` 里那份「不参与过渡」的名单是**写死的**：以后加颜色变量
只许加进过渡列表，忘了会被那条「除了细线那 4 个，其它都要在列表里」抓住。

切换的那 260ms 里还会给 `<html>` 挂一个 `theme-anim`（nav.js 用 `MutationObserver`
盯 `data-theme`，回调在下一帧渲染前跑），把**元素自己的过渡全关掉**：

```css
html.theme-anim *:not(.tk){ transition: none !important; }
```

不关的话，像主页卡片 `.card{transition:border-color .14s}`（悬停染色用的）会跟变量
抢：变量每帧都在变，元素那条约每帧被重启一次，边框看着就抖一下。主题开关里的
滑块 `.tk` 是例外 —— 它滑过去正是要看的那个效果。

| | 背景 | OLL 实心格 | OLL 描边 | 候选位灰 |
|---|---|---|---|---|
| 夜晚（默认） | 深 | **方案色（固定）** | 浅 | 中灰 |
| 白天 | 浅 | **方案色（固定）** | 深 | 浅灰 |

**OLL 的实心格颜色不随主题变** —— 选了「紫」就一直是那个紫。
只有描边和候选位灰会跟着主题换，保证两种底色下都看得清。

## 首页卡片

八张卡片里，「教程」那张整张都能点：卡片里铺一个透明的
`<a class="stretch" data-last="tutorial-basic.html">` 盖满卡片，`nav.js` 按
**上次看的是初级还是进阶**（`cube-last:tutorial-basic.html`）把它的 `href` 定下来 ——
和导航条上那个「教程」入口走的是同一条规则（`lastOf()`），所以点卡片和点导航条
效果完全一样：蓝框滑到「教程」、内容淡出、淡完再跳。

标题右边「初级 / 进阶」两个字仍是各自的链接，`position:relative;z-index:1` 压在
铺满的链接上面才点得到。铺满的链接是空的，靠 `aria-label` 给读屏一个名字。

顺带一个坑：`nav.js` 挂在 `<body>` 开头，跑的时候 `<header>`、卡片这些都还没解析到，
所以凡是碰页面里元素的事（填站标 `[data-logo]`、改写卡片 `[data-last]`、注入主题开关）
都得走 `ready()` —— 它按 `document.readyState` 决定是立刻跑还是等 `DOMContentLoaded`。

## 点公式图看大图

公式图在页面上都很小：计算器的公式表只有 30px，F2L 表格 100px，练习页的题目图
也就一百多像素 —— 看不清就得点开看。**给图片加一个 `data-zoom` 就行**，
放大镜那套（脚本 + 样式 + 遮罩配色）在共用的 `nav.js` / `nav.css` / `theme.css` 里，
各页只在生成的标记上标一下，不用各写一遍：

- 点图 → 一层全屏遮罩 + **原尺寸**的图（256px 的图就按 256px 显示，不插值放大，
  最清楚）。图底下垫一层 `--card` 的卡面色：这些 PNG 是透明底的，
  直接压在深色遮罩上，深色描边会糊掉。
- 关掉：点遮罩任意处（图上也行）/ `Esc` / 右上角的 ×；关掉后焦点回到原来那张图
  （并给它补一个 `tabindex="-1"`，`<img>` 默认不能聚焦）。
- 遮罩颜色走 `--overlay / --overlay-fg`（两套主题各一份），换主题跟着淡过去；
  开着的时候 `html.lb-open` 锁住页面滚动 —— 公式表很长，不锁就是「遮罩不动、内容在跑」。
- **挂的是捕获阶段，并且截住事件**：计算器的公式表是「整行都能点 = 把公式填进输入框」，
  只在冒泡阶段接是来不及的（那一行已经先跑完了），结果「只想看一眼图」会顺手把输入框改掉。
  同理 `Esc` 也走捕获：看图时按 `Esc` 只关图，不会把页面自己展开着的东西一起收掉。
- **哪些图能点是有讲究的**：计算器公式表、练习页的题目图、F2L 表格、
  OLL / PLL 表格里那张公式图都标了 `data-zoom`。首页那几张卡片里的图在 `<a>` 里
  （点一下是跳页），所以不标 —— **白名单制：标了才放大**，免得抢掉各页自己的点击。
  教程页那几张步骤图暂时没标 —— 想要说一声，加一个属性的事。
- 打印时不印遮罩；系统开了「减少动态效果」就不做缩放动画。
  `test/lightbox.js` 会把 `nav.js` 里那段抽出来真跑一遍（点图 / Esc / 聚焦 / 不抢别处的点击）。

## 界面层次（面板页：计算器 / 练习 / 编辑器）

面板页的东西一多，最容易出的事就是**所有东西一样重**：标题、说明、计数、
按钮、步骤小片全是同一档灰，看下来分不出哪儿是「段」、哪个是主操作。
所以这三页共用一套层次：

- **先记账、再演动画**：按「执行公式」的那一下，这一条就进历史、累积局面直接落到这一串做完的
  样子，然后画面才从第一步演起。好处是「按了就有反馈」，而且历史记录和 `cur` 从按下那一刻起
  就是一致的 —— 不会出现「记录里是整串公式、局面却停在半路」这种点进去对不上的状态。
  代价是暂停在动画中间时，画面停在半路而累积局面已在末尾（和「跳到某一步只是换个位置看」
  是一回事，下一个动作会从 `cur` 重新画）。
- **一屏只有一个主按钮**。计算器里是中间那个**播放键**：比旁边的步骤键更高更宽
  （40px vs 32px）、圆角反而更小（6px，更实更沉）、实心深色底 + 两层更重的落地投影，
  播放中再套一圈主色光环（图标 25px，压在 56×40 的实心底上）。配色走 `theme.css` 的 `--primary / --primary2 /
  --primary-fg / --primary-drop`（两套主题各一份）——**都当主按钮就等于没有主按钮**。
  它这套样子在**普通 / 悬停 / 按下**三态里都写全了：旁边那条
  `.ctrl button:hover:not(:disabled)` 比 `.ctrl .play` 更具体，少写一条，
  悬停时就会被改成浅底 + 正文色（深底配 `--text`，图标几乎看不见）。
  `test/cubesim.js` 的 `[11b]` 不只看源码，而是**按 CSS 的规则真算一遍级联**
  （解析规则 → 匹配 → 比特异性）—— 上面这个坑就是它先抓出来的。
- **小标题是这一列的骨架**：正文色 + 700 字重 + 底下一道 `--line` 细线，
  右边那个计数（`步骤 3 / 4`）退到 `--muted2`。三页用的是同一条规则，
  `test/links.js` 会核对，别只改一页。
- **文字分三档**：正文 `--text`、次要 `--muted`（说明、表头、序号）、
  最弱 `--muted2`（单位、提示、走过的步骤）。要看的数字（速度值）留在 `--muted`，
  别再往下压 —— 那是内容，不是装饰。
- **配角要甘当配角**：步骤键、单步键盘、`公式` 开合键都压到 `--muted`，
  指上去才提亮成正文色/主色。
- **步骤小片是平的**：一串公式二十来个小方块，做成立体按钮就会把整列的重量糊在一起 ——
  它们是「一层浅底 + 没有渐变/投影/抬升」的平片，只有走过（去掉底）、
  没走到（浅底）、当前（实心主色）三种状态。**指上去才浮起一层短投影**
  （走过的那几种也一样：它们本来是透明底，不给点反馈就像「点不动」）。
  这里有个坑值得记：`.moves span.done` 和 `.moves span:hover` **同分**、又排在后面，
  只写 `:hover` 的话底色和字色会被 `.done` 按住 —— 必须再写一条
  `.moves span.done:hover`。投影用中性的 `--btn-drop`，主色光晕只留给当前那一块。
- **当前这一步的高亮是一条会滑过去的色块**（和顶部导航那条 `.pill` 一个思路）：
  以前是「这块灭、那块亮」一下一下地闪；现在是一条 yellow 色块从上一片滑到下一片，
  条子本身也**平滑滚动**（`scrollTo({behavior:'smooth'})`，系统要求「减少动态效果」时仍瞬移）。
  层次是三层：小片自己的底色（在文档流里）< 色块（`position:absolute`）<
  小片里的字（那层 `<b>` 抬到 `z-index:2`）—— 所以它滑过去的路上既不会被别的小片挡住，
  也不会盖住任何一个字母。换了一串公式时直接落位（`.pill.instant` 那一下不做过渡），
  免得从上一处飞过来。
- **步骤条单行横滚，不换行**：十一二步一换行会变成「9 个 + 2 个」两行，
  看着像「被屏幕挤下去」而不是一行公式。现在一条到底（`overflow-x:auto` +
  `flex-wrap:nowrap`），**当前这一步摆在条子的视觉中心**（播放时不用跟着去找），
  两头那几步到头了只能贴边，所以是「尽量」。
  **滚动条藏起来了**（一条 6px 的横条夹在控件中间太抢眼），改由滚轮（上下都算、
  横着滚也行）、按住鼠标拖（左键 / 中键都行，中键的自动滚动圈按掉）来滚；
  手机上不接管，走浏览器原生的横划（有惯性）。滚轮只在「这一条还能往那边滚」时
  才 `preventDefault`，到头了就放行 —— 不然鼠标停在步骤条上，整块面板就再也滚不动了。
  另外两个坑记在这里：① 只动这一条自己的 `scrollLeft` —— 用 `scrollIntoView` 会顺手把
  整块面板也滚一下；② 位置必须用两个 `getBoundingClientRect()` 相减算，
  **不能用 `offsetLeft`** —— `.moves` 没有定位，`offsetParent` 会一路找到 `body`，
  算出来的值带上整块舞台的宽度，结果永远被夹在最右端（当前步老在边上跑）。
  `test/cubesim.js` 里那几条断言就是照这个造的：桩里故意给 `offsetLeft` 塞一个
  「offsetParent 是 body」的大值，谁改回去就会复现「永远贴最右端」。
- **单步键盘是一块键盘，不是十二个按钮**：底色比面板亮一档，没有描边、没有投影、
  没有渐变，指上去才浮出描边和主色字。字**保持正文色** —— 层次靠「没有按钮的壳」
  来分，不靠把字洗灰（洗灰的那版，键上的字母反而看不清了）。
- **主色（黄）只表示「当前 / 正在播」**：播放键、当前步骤、当前历史、开关 ON、
  滑杆是它；「打乱 / 复原 / 正向 / 反向 / 复制」这些动作按钮身上不该出现黄色。
  连历史里那个「反向执行」的小角标也改成了中性色 —— 它说的是「这条是怎么来的」，
  不是「当前状态」。
- **不能点的主按钮要褪回灰底**：`box-shadow:none` + `--field` 底，不然它顶着一身
  投影，看着仍然能点。
- **公式输入框有「编辑器」那点意思**：等宽 14px / 字重 500 / 字距 .2px，
  和周围的中文 UI 明显不是一条线（公式是这一页最核心的数据）。
- **纵向节奏**：section 间距统一 16px；没消息时那行提示（`.err:empty`）不占高度，
  否则「公式」和「单步」之间会白空出一整行。
- **魔方底下有一块落地阴影**（计算器 / 练习页）：没有它，立体魔方看着是「飘」的。
  这块阴影**不能挂在 `.cube` 上** —— 那是个 `preserve-3d` 的容器，给它加
  `filter` / `box-shadow` 会把它压成 `flat`，3D 立刻塌掉；而且阴影也不该跟着魔方转。
  所以是舞台上另外一块不参与 3D 的椭圆（`radial-gradient` 化得很开 = 非常柔和），
  位置和尺寸都按 `--cs` 算（跟着缩放一起放大），颜色取 `--btn-drop`。
  `--cs` 因此**也挂在舞台上**一份（阴影是舞台的孩子，不是 `.cube` 的孩子）。
- **历史每一条都能点**（回到那一步结束时的局面），所以指上去要给反馈：
  底色浮一档、字提亮；当前停的那条左侧压一条 3px 主色指示条。

## 两种模式

画布左上角切换：

| 模式 | 内容 |
|---|---|
| **F2L** | 三维魔方，涂三个可见面的颜色（默认模式） |
| **OLL** | 顶层俯视图 3×3，编辑每块的**朝向** |
| **PLL** | 顶层俯视图 3×3 + 侧面颜色 + 置换箭头，拖拽编辑 |

面板会跟着模式变：OLL 下显示「OLL 配色」，隐藏「相机」「样式」——
那两组参数只作用于 F2L 的三维渲染，OLL 图用的是它自己那套参数。

切模式不会丢东西 —— 两边的状态各自保留，撤销栈也是共用的。

## OLL 模式

```
实心 = 该块 U 面贴纸朝上（黄色朝上）
空心 = 没朝上，黄色从某个侧面露出
```

**每个非中心块记录的是"黄色朝向哪个面"**，而不是简单的布尔值：

| 块 | 状态数 | 说明 |
|---|---|---|
| 棱块 | 2 | 朝上 / 唯一的那个侧面 |
| 角块 | 3 | 朝上 / 两个侧面之一 |
| 中心块 | 1 | 永远朝上，不可编辑 |

**边框划线**就是这张图的另一半信息：哪一面露着黄色，就在那条边上画一段线。

- **点格子循环朝向**：角块三态（U → 一个侧面 → 另一个侧面）、棱块两态
- 右键点格子：直接设回朝上
- 中心块点不动
- **边框划线是实心线段**：选中的用实心格的颜色，其余的灰线**调淡到 50%**
  （候选有 12 条、有效信息才几条，不调淡会把重点淹掉）
- 边框线只作显示，不参与点击（曾经给它加过加粗热区，结果抢走了格子边缘的点击）
- 「OLL 配色」里的「显示边框划线」可以整体关掉
- 选中的划线用和实心格一样的颜色（换配色方案时一起变）

> 这套模型是从参考图反推并**逐条验证**过的：
> - **OLL 27（Sune）** 实心格是 4 棱 + 中心 + 1 角，正好等于 Sune 的已知朝向；
>   若按"实心 = 朝向错"解释就对不上。
> - **OLL 7** 图上共 5 条线，而它未朝上的块正好 5 个（3 角 + 2 棱）——
>   每个未朝上的块贡献**恰好一条**，位置逐条吻合。
>
> 角块必须记 3 态而不能只记"朝上/没朝上"：两个扭转方向在格子上看起来一样，
> 只有划线的位置不同，正是这些线在区分它们。

### 配色方案

面板「配色」里选实心格颜色，**每个方案就是一个固定颜色**，白天夜晚都一样。
色卡只显示颜色、不带文字（名字放在悬停提示里），选中实心格和对应的划线都用它：

| | | | | | |
|---|---|---|---|---|---|
| 紫 `#7E6FC7` | 靛蓝 `#4F7BC4` | 绿 `#3E9E6D` | 红 `#B94A5C` | 黄 `#FFE600` | 深紫 `#4C4263` |

「黄」**直接引用 `HEX.yellow`**，和 F2L 的顶面黄、PLL 的 U 面黄是同一个常量 ——
三个模式的黄色不会各写各的再漂移（原先 OLL 单独写成 `#E0B400`，和另外两个对不上）。
改成黄底黑框后，OLL 图正好是经典配色那种一眼就认得的样子。

主体用**中间调**而不是参考图那种深紫，是有原因的：空心格透明，实心格直接落在画布底色上，
而参考图的 `#4C4263` 放在夜晚的深底上几乎和背景融掉（只剩描边撑着）。
中间调在白底和深底上都能读。参考图那个深紫仍保留为最后一个选项 —— 白底或导出时最佳。

空心格始终是透明（`fill="none"`），所以不需要任何衬底，两种底色下都成立。

导出时描边会按底色选对比色：勾了白底就用深描边，透明底则跟随当前主题。

## PLL 模式

数据**只有一份**：8 个顶层块各自在哪个槽位（一个置换）。颜色和箭头都从它推导，
所以不存在"两份状态对不上"的可能 —— 这是靠结构保证的，不是靠同步代码。

| | 含义 |
|---|---|
| **箭头** | 这块该去哪：从它现在的位置指向它的家 |
| **侧面颜色** | 该块侧面贴纸的颜色，画在对应那条边外侧 |

划线的粗细（0.075）、距格边距离（0.085）、长度（0.60）**与 OLL 完全一致**。

**两个视图的画布尺寸也完全相同**（都是 4.208）：格间距、圆角、留白比例取同一组值。
这点很重要 —— 画布总尺寸不同的话，两个图各自缩放到同一显示区域后，格子看起来会不一样大。

箭头照第一份示例：线宽 0.07、头长 0.30、**头宽/头长 0.34**（细长的尖头，不是钝三角），
并且**从格心到格心**（`tailIn` / `headIn` 都是 0）—— 头尖正落在目标格子上。

**互换成环的两块只画一根双头箭头**（两头都有头）：方向本来就没意义，
画成两根平行的单向箭头只会让它们的头尾挤在一起。三循环才是首尾相接的单向箭头链。

箭头端点**独占一格时精确落在格心**；若同一格上落了两个以上端点（前一根的尾 + 后一根的头），
各自往回缩 `joinGap = 0.15`，留出缝 —— 否则前一根的圆头尾会直接压进后一根的三角头里。

> 踩过的三个坑：
> 1. 两端缩进曾是 0.30 / 0.34，箭头只剩格心距的 45%，头尖悬在半路像是"在中间"
> 2. 互换画成两根平行箭头时，偏移法线若从各自的 `p1→p2` 算，两根方向相反法线也相反，
>    再乘相反的符号正好抵消 —— 两根会完全重叠。改成双头箭头后这个问题自然消失
> 3. 线段用圆头端点（`stroke-linecap:round`），若和箭头尖重合，圆头会从尖外鼓出
>    半个线宽，看着"头没包住线"。所以线段两端各缩进 `头长×0.8`，藏进三角里面
**箭头颜色在「箭头颜色」里选，和 OLL 配色同一套色卡样式**，默认深紫：

| | | | | | |
|---|---|---|---|---|---|
| 深紫 `#4C4263` | 墨黑 `#1A1A1A` | 藏蓝 `#2B4C8C` | 墨绿 `#2A5F45` | 深红 `#9E2B3A` | 赭石 `#7A4A1E` |

预设全是深色 —— 箭头画在黄色格子上（还会横穿格子之间的缝），浅色在黄底上会糊掉。

**只拖方块**：把一块拖到另一块上，两块对调。交换可以生成任意置换，所以拖方块
足以拼出所有 PLL 情况 —— 拖箭头没有额外能力，还多一层"我到底抓到的是哪个"的困惑，已去掉。

拖拽手感：**按下就把方块抓起来** —— 提到最上层、跟着指针走，松手才落子；
拖箭头时从"不动的那一端"拉一条蓝色虚线示意，合法落点会高亮。

> 有个坑值得记一笔：被抓住的格子必须设 `pointer-events:none`，
> 否则 `elementFromPoint` 只会命中它自己，落点永远解析成起点 —— 怎么拖都没反应。
> 这条已经写进注释，也有测试盯着。
- 角块只能进角位、棱块只能进棱位 —— 混放会让角块多出来的那个侧面贴纸无处安放，颜色直接失真
- 「PLL 显示」里可以关掉颜色，只剩箭头（两种显示共用同一份数据）

配色是标准西式配色把魔方翻成黄顶的结果：**U 黄 / F 蓝 / R 红 / B 绿 / L 橙**。
块的旋转是绕 U 轴顺时针 Δ 步，贴纸的面 `f → (f+Δ) mod 4`。

> 这套模型是**从参考图反推并验证过**的：
> 把参考图那个角块三循环的箭头照搬进来，渲染出来的三根箭头
> （斜向左上、右侧竖直向下、底部水平向左）和原图逐条吻合。

## 交互：就地取色圈（F2L 模式）

**没有"当前画笔"这个状态。** 点哪一格，就在哪一格原地弹出取色圈，选完即走 ——
不用先去右边选色再回来点方块，省掉鼠标在屏幕两端来回跑。

| 操作 | 效果 |
|---|---|
| 左键点贴纸 | 在该格弹出取色圈（6 色 + 清除） |
| 再点同一格 / 点空白 / `Esc` | 收起色圈 |
| 点另一格 | 色圈直接转移过去，不用先关 |
| `1`–`6`（选中格存在时） | 不经色圈直接上色 |
| `0` / `Backspace` / `Delete` | 清除选中格 |
| 右键点贴纸 | 直接清除为灰色（省掉开圈那一步） |
| `Ctrl+Z` / `Ctrl+Shift+Z` | 撤销 / 重做（也可用面板按钮） |

几个设计取舍：

- **圈里会标出该格当前的颜色**（蓝环），所以点之前就知道现在是什么。
- **灰色不作为画笔**，而是作为「清」这个明确的动作出现在圈里 ——
  清除动作因此是可见、可预告的，不再是一条隐藏规则。
- **右键 = 清除**，符合图形软件里"右键取消"的通用习惯。
- **撤销栈**是特意加的：可以放心乱试，点错按 `Ctrl+Z` 就回来了。

## 导出

导出前可以在面板里设置：

| 选项 | 说明 |
|---|---|
页面图标是这个工具自己导出的 `cube-64x64.ico`（透明底，64×64）：
`<link rel="icon" type="image/x-icon" href="cube-64x64.ico">`。

| **文件名** | 默认 `cube`。`\/:*?"<>|` 这些非法字符会就地替换成 `-`（输入时就换，不用等导出才报错） |
| **尺寸** | 输出像素**宽度**，高度按画面比例自动算。预设 `64 / 128 / 256 / 512 / 1024`（网页图标 → 网页展示 → 高清），也可以直接填数字，范围 16–8000，超范围会被夹住 |
| **白色背景** | 勾上导出白底；取消则是透明底（贴到深色背景上用） |

实际文件名 = **文件名 + `宽x高`**，尺寸不同不会互相覆盖：

```
cube-256x258.png      小图标 / 缩略图
cube-512x516.png      网页展示 / PWA 图标
cube-1024x1033.svg    高清，矢量可无损缩放
```

各档大致用途：`64` 小图标、`128` 图标、`256` 应用图标/缩略图、`512` 网页展示、
`1024` 高清。默认 `512`。

面板里有一行实时提示，直接显示当前会导出成什么名字；改名字、改尺寸、动相机（会改变画面比例进而改变高度）都会跟着更新。

四种输出：

- **PNG** — 从 SVG 离屏渲染，尺寸就是上面设的那个宽度
- **SVG** — 矢量，宽高按设定值写进 `<svg>` 标签，可无损缩放
- **JPEG** — 同上光栅化，质量 0.92。**JPEG 不支持透明，所以强制白底**（否则透明处会变黑），
  就算没勾「白色背景」也一样
- **ICO** — 网页图标用。浏览器没有 ICO 编码器，所以自己拼文件头：
  6 字节目录 + 16 字节条目 + 一张 PNG（Vista 起支持 PNG 承载）。
  **尺寸封顶 256**（图标惯例，再大没意义，且 256 在 ICO 里写作 0）。
  ICO 是 32 位带 alpha 的，**支持透明**，所以它和 PNG/SVG 一样尊重「白色背景」开关 ——
  取消勾选即可得到透明图标（浏览器标签页图标一般都要透明的）

「白色背景」开关对各格式的影响：

| 格式 | 不勾选时 |
|---|---|
| PNG / SVG / ICO | 透明底 |
| JPEG | **强制白底**（格式本身没有 alpha 通道，不铺白透明处会变黑） |

> ICO 这 22 字节的头是手写的，所以专门验过：生成的文件用 PIL 能正常打开、
> 尺寸报 256×256、像素采样正确。

## F2L 公式合集（f2l.html）

独立的一张速查表，双击打开即可。**固定白底**（不跟随系统深色模式 —— 这是打印/速查用的表）。

三张公式表**打印时分页是连续的**：卡片不拦着分页（`break-inside:auto` + `overflow:visible`），
一张表写不下就接着排到下一页；只禁止「一行被劈成两半」（`tr{break-inside:avoid}`），
标题用 `break-after:avoid` 拴住后面的内容 —— 否则 PLL 那种「只有一个大标题」的页首
会被孤零零留在上一页。F2L 的红/绿 F 表头是 `<thead>`，换页后会自动再来一遍。
左列「红色为 F 面」、右列「绿色为 F 面」，
共 3 节 21 行 39 个情况。点公式即复制（会自动去掉空格，方便直接粘进计时器）。

| 节 | 行数 | 空位 |
|---|---|---|
| 需要特殊处理的几种情况 | 7 | 第 7 行右格 |
| 白色朝上的情况 | 6 | 第 1、2 行右格 |
| 简单情况 | 8 | 无 |

图片命名规律和表格位置是**严格对应**的：

- `01a`/`01b` … `06a`/`06b` → 第一节第 1–6 行的左/右格
- `07` → 第一节第 7 行左格（右格为空）
- `08`、`09` → 第二节第 1、2 行左格（右格都为空）
- `10a`/`10b` … `13a`/`13b` → 第二节第 3–6 行
- `14a`/`14b` … `21a`/`21b` → 第三节第 1–8 行

即 `a` = 红色为 F 面（左），`b` = 绿色为 F 面（右）。13 + 10 + 16 = 39，与图片总数吻合。

> **「绿色为 F 面」是 F2L 独有的**：从这儿点 ↗ 跳计算器时，`b` 版的链接会带一个
> `@g:` 前缀（计算器收到就先做一个 `y`、视角补 90°，把绿面摆到前面）。
> 这个判据必须写成「数字 + b」（`01b`、`02b`…）—— 曾经三个公式页都跟着抄了
> `/b$/`，于是 PLL 的 **Ab / Gb / Jb / Nb / Rb / Ub** 六条（末尾那个 `b` 是
> 「第二个变体」的意思）也被当成绿面朝前，跳过去会先转 90°，摆出来的图和表里的对不上。
> 现在 OLL / PLL 直接写 `green = false`，`test/cubesim.js` 会把三个页面真渲染一遍、
> 逐条查链接里有没有 `@g:`。

> 公式严格照原表誊录，**包括原表里的 `U'2`、`L'2` 这类写法**
> （通常记作 `U2` / `L2`）。表格的行结构是程序化检测横线得到的，
> 不是肉眼数的 —— 起初我按估算行界读，第三节少数了一行、第二三节还整体错位了一行。

三张表都是**每行一个情况**、点公式即复制，右上角可切**白天 / 夜晚**，
滚过一屏后右下角出现**回到顶部**（纯图标、无文字）。文案尽量压到最少 ——
页头只留一个短标题，列头用「红 F / 绿 F」，复制提示直接显示公式本身。

## OLL / PLL 公式合集（oll.html / pll.html）

风格与 `f2l.html` 一致（固定白底、橙色分节条、点公式即复制）。
OLL/**标准编号 1–57**，按顶面图案分四张表：十字、单点、一字、拐角
（分组不变，但组内编号是标准值，所以每组里编号不连续，例如单点是
`1 2 3 4 17 18 19 20`）。**PLL 用标准的字母编号**（`Aa` `Ab` `E` `F` `Ga`…`Z`，共 21 个），一张表全列。
不用数字 —— 字母序既是官方习惯，也能直接和公式库、网上资料对上。

每个情况**只收一条主公式**，照图摆好直接做就行；**点图可以看大图**
（放大镜那套见上面「点公式图看大图」）。

> 早先这里每个情况还收过**多条备选写法**（点图片展开，每条配一张「对应朝向」的图，
> 图顺时针转 m×90°）。后来数据里只留了主公式，那套交互也就没了 ——
> 相关代码已经清掉（`oll.html` / `pll.html` 里的 `has-alts` / `.alts` / `row(n, alg, alts)`）。
> `tools/verify.py` 和 `test/links.js` 里那套「备选 + AUF 步数」的校验还在：

公式取自知乎「小狼啊小狼」的 CFOP 系列，但**逐条做过朝向校验**，
不能拿来就用的一律换掉或留空：

| | 原式直接用 | 换成朝向吻合的 | 人工校对 | 留空 |
|---|---|---|---|---|
| OLL | 50 | 1（51） | 6（4、5、6、7、25、26） | 0 |
| PLL | 16 | 4（9、10、12、13） | 1（6） | 0 |

朝向对不上的一共 12 条，都已解决 —— 5 条是"原式差 2–3 步 AUF"（照图摆好会做错），
由人工补了照图直接能用的写法；其余从公式库找到朝向分毫不差的替代。

> 人工给的两条有笔误，都验出来了：OLL 07 的 `R' U' R U' R U'2 R` 第三段 R 少了撇号
> （下两层没复原），补成 `R' U' R U' R' U2 R`；补撇后与图完全吻合。

校验方法：用自写的三阶模拟器把公式**逆运算作用在复原魔方**上，得到它解的
局面，再和图里读出的签名（顶面 9 格 + 侧边 12 条划线／12 条色带）比对 ——
只有**分毫不差**才算"照图摆好就能用"。差一步 AUF 也算对不上，因为那意味着
照图摆好直接做公式会做错。

> 过程中踩到的坑：
> 1. 带 `x'`/`y` 的公式**净效果是一个整体旋转**，所以它解的局面不是
>    `A⁻¹(复原)` 而是 `A⁻¹(r(复原))`，其中 `r` 可由**中心块**读出来
>    （面转永远不动中心块）。不修正的话一大半 PLL 都会被误判成"对不上"。
> 2. 给公式库建索引时**不能把 4 个 AUF 旋转都收进去** —— 那样会匹配到
>    同一个算法转过 90° 的版本，看着吻合，实际仍需手动 AUF。
**OLL 编号已换算成标准编号**（1–57），文件名同步重命名。换算关系由
「用标准编号的公式反推局面、再和每张图匹配」得到，是严格双射（57↔57 无重复无遗漏）。

> 3. PLL 9 原来的图是**单一对换**（只换了 UB/UF 两条棱），这在三阶上奇偶性不允许，
>    任何公式都解不了。重出后（`BFRLLLFRBFBR`）已找到朝向吻合的公式（标准 F-perm）。

## 公式朝向校验（tools/）

公式对**不等于**图对：公式本身可能没错，但图上的摆法如果和它要求的摆法差一步 AUF，
照着图摆好直接做就会做错。这类问题光看图看不出来，必须算。

```bash
python3 tools/verify.py              # 校验 oll/pll 的公式与图、教程页的公式与步骤图是否一致
python3 tools/verify.py --find 7  oll  # OLL 7 朝向对不上时，搜能用的写法
python3 tools/verify.py --find T  pll  # PLL 用字母编号（Aa..Z）
```

做法：用 `tools/cubesim.py` 把公式**逆运算作用在复原魔方上**得到它解的局面，
再和从图里读出的签名比对（OLL 是「顶面 9 格 + 侧边 12 条划线」，PLL 是「12 条侧面色带」）。
**只有分毫不差才算通过** —— 差一步 AUF 也算对不上。

细节和踩过的坑见 `tools/README.md`。当前 78 条全部通过。

## 数据模型

三个面各是一个 3×3 数组，按「从上到下、从左到右」书写：

```js
{
  top:   [['gray','gray','gray'], ['gray','yellow','gray'],  ['gray','gray','gray']],
  left:  [['gray','gray','gray'], ['red','red','gray'],      ['red','red','gray']],
  right: [['gray','gray','gray'], ['gray','green','green'],  ['gray','green','green']]
}
```

投影是一个针孔相机，`屏幕坐标 = 焦距 × 相机坐标 / 深度`，那个除法就是近大远小。
相机在 `(-1,-1,elev)` 方向，所以可见面固定是 **顶面 z=3、左面 x=0、右面 y=0**。

参数：

| 参数 | 默认 | 作用 |
|---|---|---|
| `elev` | 0.6 | 相机方向的 z 分量。越小俯角越低、顶面越扁 |
| `dist` | 14.0 | 相机距离。越小透视越强 |
| `gap` | 0.10 | 黑色边框宽度 ÷ 小方块边长 |
| `radius` | 0.10 | 贴纸圆角 ÷ 小方块边长 |
| `shading` | false | 明暗 |

> 因为只画那三个面，相机必须真的在它们外侧，即要满足
> `1.5 + dist·elev/√(2+elev²) > 3`（相机高于顶面）。
> 俯角调得越低需要的距离越大，`elev=0.25` 时约需 `dist > 9.4`。
> 界面滑块的下限已经考虑了这一点。

## 计算器的拍照

`calc.html` 右上角的相机键把当前局面存成 PNG。舞台上的魔方是 CSS 3D 拼的，
DOM 截不了图，所以 `calc.html` 自己把局面画成 SVG 再栅格化 —— **不走 `cube.js`**：

- `cube.js` 那套渲染是**固定视角**的立体示意图（相机只能在 `(-1,-1,elev)` 方向），
  拖过视角之后拍出来和屏幕对不上；
- 它还有自己一套颜色，F 面是 `#C00000`，而舞台上用的是 `#C41E3A`，
  拍出来会和屏幕「不是一个红」。

现在用的是页面自己的模型 + 和舞台**逐字相同**的变换：
`new DOMMatrix('rotateX(view.x) rotateY(view.y)')`（旋转交给浏览器解析，
手写矩阵很容易把 rotateX/rotateY 的先后、以及 CSS 的 y 轴朝下搞反），
再自己按 `1 - z/1400` 做透视除法、按 `stage.clientHeight` 补上
`perspective-origin:50% 48%` 那 2% 的偏移；颜色取自页面自己的 `COLOR` 表。
背面剔除按法向（和 `backface-visibility:hidden` 同一条判据），画的时候按深度排序。

内缩和圆角都**在格子自己的平面里**量（内缩 0.042、贴纸圆角 0.095、塑料壳直角），
再把点投到屏幕上：直接按屏幕上的边长去缩是不行的 —— 侧面被透视压扁时，
一缩就把整张贴纸挤成一条线，塑料缝会显得特别宽。

> **塑料壳不要跟着倒角。** 舞台上 `.cubie i` 是倒过角的（0.035），照抄到照片里
> 会出事：四个格子交汇处会留下一个小洞，舞台上洞后面是方块内部的深色塑料
> （看不出来），照片后面是白底 —— 于是每个格子交点都变成一个白点，整块看着镂空。
> 所以塑料壳保持整格的直角四边形，只给**贴纸**倒角。

> 两个坑，都有测试盯着（`test/cubesim.js` 里会拿一套独立写的投影当参照逐张贴纸核）：
> 1. **`DOMPoint.matrixTransform` 不做透视除法**。写成
>    `new DOMMatrix('perspective(1400px) …').transformPoint(p)` 得到的是正交投影 ——
>    同一个面里近的格子和远的格子一样大，一眼就看出「透视不对」。
>    透视必须自己除。
> 2. **贴纸是内缩过的**，拿贴纸的包围盒去归一化，位置会系统性偏一点；
>    要拿「整格」那圈点（塑料壳 / 参照的格子四角）来归一化。

（另外：舞台高低于 ~350px 时，左右两个折角键和右下角的缩放摞本身就会挤上，
这是老问题，和拍照无关；常见的桌面/手机尺寸下 `test/links.js` 会逐对核对不重叠。）

`test/pll.js` 里最重要的一条是**「颜色能从块的身份唯一反解出来」**。
它一次性验证了整套颜色/旋转模型，而且正是它抓出了
「角块可以放进棱位」这个模型级 bug —— 角块有 2 个侧面贴纸、棱块只有 1 个，
混放会让多余的贴纸无处安放，颜色直接失真。现在角/棱分离是硬约束。

`test/cubesim.js` 里还盯着一条容易回退的细节：**点粘贴键不许弹「查看剪贴板」授权框**。
`navigator.clipboard.readText()` 一读就弹（Chrome 每次点都弹，Firefox/Safari 也弹），
所以页面先用 Permissions API 查 `clipboard-read`：只有已经是 `granted` 才真读；
`prompt` / 问不到（Firefox、Safari 不认这个名字）都一个字不读 ——
退回「本页刚复制的那条」，再不行就把光标放进输入框提示按 Ctrl+V。
想让它直接读的话，在浏览器站点设置里把剪贴板允许一次即可。
